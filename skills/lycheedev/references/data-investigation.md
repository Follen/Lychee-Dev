# Data investigation

Reuse the selected pin and local/CDN source. Preserve product, full build, region,
locale and definitions. The resolver can discover missing installation identity;
a named target list is not the supported-product catalog. Resolve ambiguous
metadata instead of selecting a sibling client or changing the project lock.
Matching builds do not merge products or local/remote delivery configurations.

Discover typed requests and result shapes with `data agent schema`, then use one
owned session. Prefer the advertised domain task when it answers the question;
otherwise discover fields/relationships and construct a typed plan. Localized
names need disambiguation by ID, class/rank or relationships. Catalog enumerates
definitions, not installed table availability. Field names alone establish no
foreign key. Semantics describes original flags/enums/conditions, not whether
every condition applies to a selected record.

## Interpret and retain results

Keep column order, positional rows, nested arrays and exact integer lexemes;
never round IDs/masks through JavaScript Number. Use typed literals for values.
A query result handle belongs to its living session. Page/export read that result
without rerunning it; offsets are not mutable-source cursors. Read the schema's
nested handle and export fields instead of guessing names. Capture persists the
entire retained result; a handle or one exported page is not a CAP.

`complete` describes the requested source/result scope, not whether a page is
last. Missing keys retain readable partitions and partial coverage; placeholders
are not decoded fields. Empty partial results, bounded aggregates or CSV cannot
establish full-build absence. Static DB2/Hotfix values do not prove server behavior.
Use explicit [Hotfix overlays](data-hotfix.md) for changed values.

Release unused handles and close the session. Cancellation of outstanding work,
deadline or worker loss invalidates session handles; retain committed captures
and never automatically replay uncertain work. After a publication error inspect
its completed-capture facts/catalog before an intentional new action.

## Diagnose the named failure

Correct identity, missing content/key, integrity, field/type or resource errors
at their reported boundary. Use schema/error details; keep the original pin and
offline restriction. No guessed CDN route or silent source fallback. A narrow
row filter cannot fix a shared-metadata admission failure. Resource ledgers are
logical work, not measured RSS; explain/analyze scopes must be read as returned.
Continue independent useful work and report the blocked scope rather than turning
a failure into an empty-success answer.
