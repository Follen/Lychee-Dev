# Publishing and backup choices

Use CLI discovery for the requested platform, resource and action, then its
nested input schema. Dynamic categories, versions, tiers, channels, accounts,
roles and related resources come from that platform's queries. Keep their parent
identity; equal labels or numeric IDs across platforms are not interchangeable.

NewBee official CLI and Creator are explicit channels. Use the selected channel's
capabilities; a missing official operation does not silently select Creator.
DD retains a task-owned session or explicitly binds the chosen GUI account.
ModUs main-client and Creator credentials are separate sources. CurseForge Core
query keys and upload tokens have different purposes. The CLI owns credential
handling; do not copy passwords, cookies or signed URLs into commands or reports.

Prepare local inputs with `--plan` and inspect the result. It performs local
validation; live account ownership, dynamic options and platform acceptance
remain execution checks. Preserve omissions versus explicit clear/null/false/0
according to the command schema. Author intent determines visibility and payment;
a hidden/review flag is not necessarily access control. In particular, publish
Heybox WA only with the explicit public scope documented by its schema.

Retain the original request, artifact hashes, remote IDs and receipts. Reuse an
acknowledged upload when continuing metadata work. An absent reply after a write
requires status/readback of that original operation, never a fresh duplicate.
A verified resource identity or upload is distinct from moderation approval.

For backups, select exact addon/material/font and account/realm/character inputs.
Keep generated native manifests with their original archives. Preview deletion
and inspect reference protection; filters select candidates, explicit IDs select
writes. Recover each item under its original operation when a batch is interrupted.
