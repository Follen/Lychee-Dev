# Source relationships and bounded context

Read when callers, cross-file implementation, load context or semantic resolution
can change the answer. Simple declaration lookup can stop earlier.

Choose the returned symbol ID by repository, commit, path and scope. Same spelling
does not join declarations. Use refs for edges and context for definition,
excerpts, relations and available loading evidence; consult installed help.
Confirmed semantic resolution, static candidates and unknown edges have different
strength. Generated API declarations need not contain implementation bodies.

For a third-party addon, use its separate pinned client API environment when
needed. Retail is not a substitute for Forever. A wow-ui-source pin supplies
its own environment. Check the returned environment identity; missing semantic
support leaves a gap, not proof of absence. Emmy-inferred types do not prove
runtime behavior, and static-only intentionally limits the evidence.

Each command owns its cursor. Retain snapshot, symbol, environment, direction,
analysis options and budgets across pages. An ending page cannot erase missing
earlier pages or dynamic edges. Change scope without the old cursor. Inspect
truncation before raising a bound; request the omitted original range if useful.

Mapping completeness is not a validated TOC/XML load closure; use
[addon validation](addon-validation.md) for that. Cross-repository relations need
the matching fixed target source. An environment declaration or same-named symbol
does not prove a dependency loaded. Leave unresolved binding edges open.

For a concrete value/operation question, use [value flow](source-value-flow.md);
ordinary relation traversal does not establish secret propagation. Optional
[session reuse](source-research.md#optional-native-session-reuse) changes cost,
not evidence strength or cursor identity.
