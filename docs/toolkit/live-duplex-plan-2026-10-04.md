# 双向 mailbox 方案入口

2026-10-04。状态：协议候选已实现，离线验证正在整合；原生写入没有合格的生命周期保证，仍拒绝写入，未实机验收。当前代码与限制见 [实施合同](live-duplex-implementation-2026-10-04.md)。
任务分支：`codex/duplex-mailbox`。不做旧协议兼容，不保留 LoD 输入或 LoD 回退。

## 推荐形态

插件创建固定通信区，CLI 沿 build 配方和具名 Lua 路径定位，正常通信不再靠
LoD 插件、按键或色块。`inbox` 接收 CLI 消息，`sendbox` 发布插件状态和结果。
插件拥有独立的私有执行记录，公开邮箱的数据不能直接决定执行权限。

```text
CLI -> inbox   -> 插件私有校验、挑战和执行状态
CLI <- sendbox <- ready、heartbeat、回执、结果和退役许可
```

同一进程只允许一个未结束的业务请求。初版预留一份完整请求区，候选上限
1 MiB（1048576 字节），分为 256 个固定 4 KiB 逻辑片；这些是传输分片，
不是 200 个 LoD 插件槽位，也不要求每片各自创建一个 Lua 表。
分片确认只允许传完当前请求，不允许覆盖已收到的片或开始另一项业务。

每条消息绑定进程创建身份、build、runtime、角色、session/owner、区域世代、
请求编号和序号。时间戳用于审计；超时各用本地时钟。插件独立验证标准 SHA256，
校验范围包含解释消息所需的字段和精确内容；摘要不能替代身份、挑战和执行校验。

## 业务与控制

正常流程为：传输并验证 → 私有准备和新挑战 → 精确提交 → 执行一次 →
插件明确 success/failed/cancelled → CLI 验证并持久保存结果 → 准确结果 ACK →
插件 RELEASED。完成这个流程后，才允许写下一项业务。

## 反复执行的内存占用

140 条顺序命令复用同一份邮箱，不能累积 140 份源码、函数和结果。addon 只保留
当前请求、一个未确认结果、最后一个已释放请求的摘要，以及固定数量的控制记录；
完整历史放在 CLI 磁盘。执行静止后清掉无用源码、分片副本、编译函数、环境和
受管回调引用；结果在准确 ACK 后释放。未清理的资源不能假报 RELEASED。

1 MiB 是内容容量。若目标布局经验证每个 TValue 为 24 字节，每个数字存 4 字节，
固定 payload 实际为 6 MiB；故障同时保留新旧两份时为 12 MiB。表/header、
当前源码、编译对象、结果和分配器开销另计，尚无实测总峰值。
自然 GC 前临时垃圾可使内存波动，解除引用也不要求工作集马上下降；
验收要检查连续 140/1000 条后是否出现长期保留增长，不能每条强制 GC 掩盖问题。
探针自行向全局保存大对象或创建未受管资源的增长须另算，不能归给邮箱。

取消、关闭、结果确认等使用独立控制记录、日志和写入锁。关闭不排在无回执的
取消后，控制不排在被它取消的业务后。控制超时不伪造执行终态，不刷新业务预算。
异步探针可合作式取消；正在占用 Lua 主线程的同步代码无法承诺即时中断。

## GC 后怎么重新写

正常路径用可检查的强根保留固定区域；不能用一次 full GC 测试证明以后安全。
若区域真的丢失，由插件自己的 supervisor 重建，宿主不能修补旧地址：

1. 私有状态先撤销旧区域，拒绝迟到的旧提交；执行记录独立保留。
2. 插件创建新区域，发布新的 arenaGeneration、布局、校准数据和修复挑战。
3. CLI 确认旧数据和控制 writer 全部停止，再重新定位和完成修复握手。
4. 私有记录确认原请求未执行时，重传同一 ID、同一内容，更新传输次数。
   已接受提交或正在执行时只观察、控制；已有结果时只取回原结果。
5. 执行记录、controller 或原 runtime 丢失而无法证明原执行状态时，保留 unknown，
   禁止自动重跑；已经验证落盘的结果仍有效。原预算不因修复延长。

正常只复用一份区域；故障最多保留一份旧区域，继续故障则明确阻塞修复。
这解决丢失后的重新定位和恢复，不提供跨进程对象生命周期锁：最后一次检查后
对象被释放、而旧内核写入尚未完成的窗口仍需作为实测和投产边界。

## ready、doctor 和界面

sendbox 明确区分传输可用、新业务可用、控制可用，并发布有版本的 heartbeat。
没有发布或样本过旧不能直接判为“插件没装”或“没有进入角色”。同 build 的两个
实例也分别绑定进程、角色和 runtime，不能因共用安装而共用连接。

每次可能驱动游戏的 live 调用前都运行 doctor；新协议实现后，CLI 还须在动作前
强制执行对应能力检查。业务 busy 不应挡住取消和关闭。当前 doctor 的检查范围
有限，本轮 Skill 已明确其能力边界，不把现有 healthy 当作游戏就绪证明。

跳动荔枝只在 addon 实际执行 probe 时显示，唯一文字为 **Agent执行中**。
传输、准备、等待 ACK 和空闲连接都不显示这一执行状态。

## 切换条件与详细材料

这条分支的新版本必须删除 200 个 LoD 插件和全部槽位运行依赖，不打包备用
LoD，不在 mailbox 出错时降级到 LoD。数组布局、Lua SHA256、完整载荷性能、
跨 build/多实例、取消关闭和 GC/重建验收仍待实现和验证；未达到条件的 build
返回明确不可用，未达到发布条件则不发布，不通过保留旧输入绕过这些问题。
迁移先保全并退役准确旧连接，再一次切换 CLI、addon、安装器和 Skill；
新协议不接收旧消息，也不把旧未知请求当作新请求重发。
