状态：完整验收设计；部分用例已有 Go/Lua 实现，不代表全部通过。日期：2026-09-23（本次修订新增 11a 工作台能力回归矩阵 WKB-01..13，LUA-07 改为分项引用 WKB 用例，§16 增加工作台发布判定）。

## 1. 验证原则与结果状态

测试通过新模块接口和真实 CLI 进程观察行为，不断言旧内部函数调用顺序。纯解析直接测试；文件、SQLite 与 Git 用临时真实环境；外部 CDN、Hotfix 和游戏信号用可控 adapter。最后另做真实网络和真实游戏验证。

旧测试保存的正确行为、二进制样本、异常输入与来源证据可以继承；旧命令输出、旧配置结构和历史默认行为不作为新产品的兼容合同。旧实现的已知错误不能被固定成新的 expected value。

每项结果为 `passed / failed / blocked / not_run / not_applicable`。缺客户端、未登录、网络不可用或无 GPU 的项目不能记为 passed。每个 advertised 能力都必须有对应平台的证据。

P0 是交付阻断项；P1 在对应能力发布时同样必须通过，但可按模块分组运行。计划中没有“全部功能通过但并发和收尾后补”的发布状态。

优先验收完整用户场景：固定目标、源码与数据研究、游戏运行、结果交接和中断
恢复。低层算法保留精确单元测试；调用方不需要经过内部阶段函数才能测试用例。
`live run` 从 session 取身份，`live resume` 从 operation 取身份；参数覆盖必须拒绝。
专门验证报告已归档而清理失败时，结果仍为 verified、cleanup 为 pending、complete
为 false，正文和恢复 ID 可用；归档缺失/损坏不能仅凭阶段记录变成 verified。
skill 测试应验证这一判断，而不是匹配文案或要求 agent 手动操作协议。

游戏恢复须覆盖两个容易混淆的崩溃窗口：意图已落盘但尚未发送、发送已发生但
发送回执尚未落盘。两者不能靠“回执缺失”决定补发。前者没有游戏证据时保持未决；
后者只有收到原请求的有效游戏证据才继续，后续新阶段可执行、原输入不得重发。
现有完整生命周期 fixture 对六次提交分别覆盖这两类窗口；不等同于进程强杀或真机证据。

## 3. 测试组织与证据

建议的新验证入口为 `go run ./tools/check --suite <name>`，由 Go 实现。可组合 suite：contract、offline、process、protocol、native、network、client、package、performance、skill。该入口尚未存在。

```text
tests/
  contract/             CLI、结果、命名和依赖规则
  integration/          SQLite、Git、文件、HTTP 以及跨模块使用
  process/              两个或多个真实 CLI 进程
  protocol/             Go 与 Lua 共享的信号/报告样本
  native/               Windows 消息接收窗、WGC 与 QR
  client/               用户真机验收记录格式；CI 不运行游戏实测
  fixtures/             固定小样本及来源清单
  skill/                工作流情景和工具轨迹评估
  performance/          冷热启动、内存、IO、并发和捕获
```

每份测试报告保存 testId、suite、seed、gitCommit、工具链/平台、发行版本、协议版本、workspaceId、实际输入、实际固定引用、开始结束时间、状态、断言结果和产物摘要。实机额外记录游戏 Build、Interface、角色标识的受限表示、窗口状态、分辨率、UI 缩放、显示缩放和权限级别。

测试使用合成账号、清理过的二进制样本和必要片段；禁止把完整用户 SV、账号路径或私有探针作为公开 fixture。失败保留最小复现、阶段日志及必要截图，正常流程不上传整屏。

选择、配置内容与键校验、父集合不变、DBD 精确固定和在线/离线重复解析。
目标准备证据只证明所观察的元数据，不证明所有表可读或游戏在线。后续 DB2、SQL
和资源读取应使用同一个客户端路径；客户端更新后拒绝原身份，不静默重选 Build。
符号 DBD 引用并发解析时分别保留各自 HTTP 观察，不以缓存 CAS 的胜者覆盖另一
请求的目标。引用缓存缺失、损坏、取消、重定向、超大响应与无效 SHA 均有反例。
当前对应测试位于 `internal/records/target_test.go`、`definition_revision_test.go`
和 `internal/command/target_test.go`。

远程目标准备从 `target resolve --product` 进入：地区唯一行、精确 Build 约束、
版本与 CDN 清单一组离线观测、配置 MD5 与归档 SHA-256、父集合保留、同配置并发
单下载，以及缺缓存、截断、重定向、超预算、错误摘要和取消的反例。在线失败不得
转用旧观测；离线不得宣称当前线上版本。对应 `remote_catalog_test.go`、
`remote_target_test.go` 与 CLI 目标测试。

项目默认目标：init/lock/status、最近祖先发现、显式 snapshot 不读取项目、锁定
引用完整性、跨 workspace 携带、损坏近层项目不借上层、无锁不得导入默认引用、
并发发布只暴露完整锁、取消不替换、未知 schema 不覆盖。源码检查/查询需要真实
CLI 进程证据，数据需至少一个完整 fixture 查询；run/resume 不得接受项目覆盖。
Windows 还需验证已打开读句柄不阻断锁替换，旧句柄仍读旧值、新读者得到新值；
仅在无读者时 rename 成功不算并发验收。当前采用 Go Root 文件操作，不以重试
普通 os.Rename 代替该语义。
命名目标配置及可变意图的刷新仍需独立验收。

CDN 内容验收由共享读取接口覆盖 DB2 单行/页、SQL 和资产检查。范围测试拒绝
200/重定向/多段/压缩/错总长/截断/超长并验证取消和关闭；索引测试覆盖 loose、
archive、group 的 footer/TOC/页完整性。缓存测试需覆盖同键并发只下载一次、
离线不触网、缺失/损坏失败。真实 CN 配置存在长度提示与认证索引不符的样本，
以服务端有界响应获知长度后认证索引，不能靠放宽 Content-Range 校验通过。
真实 Map 在线/离线、SQL、资产与分页证据见实施状态；其他产品及冷读性能待验收。

## 8. 多 Agent / 多进程回归

下列测试必须启动真实的独立 CLI 进程；goroutine 测试和 go test -race 不能替代文件锁、数据库与进程退出验证。用 barrier 控制交错点，不依赖随机 sleep 碰运气。

| ID | 级别 | 进程 A / 进程 B | 必须观察到的结果 |
| --- | --- | --- | --- |
| CON-01 | P0 | 游戏探针等待结果 / DB2 查询 | B 在 A 完成前返回；两者各自结果正确，无全局任务锁 |
| CON-02 | P0 | 游戏重载/ACK / 源码查询 | B 不触碰窗口；A 使用原绑定和 nonce 完成 |

## 9. 执行状态机与故障注入

协议 adapter 能记录所有发送动作并在指定阶段强制中断。每个副作用分别在“意图落盘前、意图落盘后发送前、发送后确认前、确认后”注入退出。使用同一 operationId 恢复并检查全部历史效果。

| ID | 级别 | 场景 | 必须观察到的结果 |
| --- | --- | --- | --- |
| RUN-01 | P0 | 完整探针闭环 | loaded、reported、persisted、verified、acknowledged、cleaned 均有匹配证据 |
| RUN-02 | P0 | 游戏内 Lua 报错 | 保留失败正文，完成采集收尾，probeStatus 与传输状态分别准确 |
| RUN-03 | P0 | 旧 QR、错误请求/角色/Build/摘要 | 丢弃不匹配信号，不触发 reload 或 ACK |
| RUN-04 | P0 | 提交成功但宿主立刻退出 | 恢复不盲目补发，无法证明的效果保持 unresolved |
| RUN-05 | P0 | 输入或输出 reload 超时 | 恢复复用原 nonce，不重复 reload；两类 reload 不混淆 |
| RUN-06 | P0 | 报告已在 SV，但没有观察到 mtime 更新 | 依据精确报告和阶段证据处理，不仅凭 mtime 拒绝/接受 |
| RUN-07 | P0 | 报告 verified 后 ACK 失败 | 返回 capture；resume 只补 ACK 和清理，不重跑或重载 |
| RUN-08 | P0 | ACK 已确认但清理没有有效帧 | 不能把无帧当无标记；保持收尾未决并可继续 |
| RUN-09 | P0 | 执行中取消、窗口关闭、进程崩溃 | 释放宿主资源；无法确认的游戏效果标明，绝不强杀游戏 |
| RUN-10 | P0 | 正文超过 QR 容量或 10 KiB | 仍走完整 SV；QR 大小不随正文增长 |
| RUN-11 | P0 | 报告/队列达到边界与超一字节/一项 | 边界正确，超限明确；没有隐藏截断或越界写入 |

| RUN-14 | P0 | 读现有 capture、宿主重新启动 | 不执行探针、不要求游戏在线；原始字节校验一致 |

| RUN-16 | P0 | 正常 reload 更换 Lua 会话标记 | 只有匹配原 nonce、相同进程/角色/Build 才更新绑定，其他变化拒绝 |

## 10. Windows 原生后台通路

先用自建消息接收窗口验证 Win32 参数，再用真实游戏验证语义。模拟器成功不能替代游戏验证。

首连场景使用 `live connect`（宿主自动发送 `/dev bridge identify <nonce>` 身份标记
与固定 `/dev connect`，用户零 `/dev` 输入）：验证候选发现与安装/在线区分、身份
标记的 probeNonce 回执关联、唯一/歧义选择、PID/安装过滤、角色约束、同屏多个
回执拒绝、缺失或过期画面失败，以及普通结果不泄漏内部协议。重连与执行不得沿用首次发现
的宽松匹配；必须核对原进程/角色/nonce。`--capture-area` 只限定选定窗口中的
捕获区域，省略时整窗捕获。断开只停止连接，不删除报告或修改别人的任务。

从该连接直接 `live run --session <id> --file <probe.lua>`，验证账号目录自动
选择、Unicode/空格名字、不同角色/服务器排除、零/多个候选、扫描预算、路径跳转
拒绝。选择失败不得留下操作或发送输入；选择成功后新增其他匹配目录不得改变原
操作及恢复的账号。首次登录可显式 `--account`，目录只是位置选择，不能替代
后续报告的精确请求校验。旧/损坏 SV 内容不能参与发现或被自动导入。

| PKG-05 | P0 | 发行文件白名单和离线启动 | 不含 Python、旧内核、用户数据、本地任务、测试/调查资料或空壳代理 |
| PKG-06 | P0 | 安装/卸载有用户文件的目录 | 只处理明确拥有文件；保留额外文件；删除数据需显式范围 |
| PKG-07 | P0 | release 版本、tag、schema、校验和 | 可追溯且一致；第三方许可及署名齐全 |
| PKG-08 | P0 | Windows 发行目标 | 声明能力与实际验证一致；产品只发行 Windows amd64（2026-09-23 裁决），非 Windows 平台不声明、不验收 |

## 14. 性能回归与预算

在 S0 固定机器、数据集、语言、网络响应、工具链与测量方法。旧/新版本交替运行；冷缓存与热缓存分开。耗时样本至少 20 次，报告中位数及 p95；资源报告峰值 RSS、读写字节、网络字节、线程/句柄和取消耗时。

| ID | 场景 | 建议初始门槛 |
| --- | --- | --- |
| PERF-01 | version/help/热 doctor | 不启动业务 IO/网络/捕获；相对固定原生基线显著回退必须解释 |
| PERF-02 | 固定源码及数据热查询 | 中位耗时回退不超过 15%，p95 不超过 20%，峰值 RSS 不超过 20% |
| PERF-03 | 固定冷查询及资源导出 | 单独报告不可避免的下载；相同响应下不因整合重复拉取/解析整库 |
| PERF-04 | 100 次捕获和完整调查 | 预热后无持续资源增长；所有会话、临时输入和 owned 资源正常收尾 |
| PERF-05 | 4 个查询 + 一个实时调查 | 资源准入有效、无饿死；记录相对单独运行的耗时，不套用单进程绝对预算 |
| PERF-06 | 窗口输入到回执、报告到清理 | 各阶段分别统计，游戏加载时间分开；不以总耗时掩盖 ACK 卡住 |

以上数值是待基线验证的政策。S0 发现噪声超过阈值时先修改测量方法，再冻结门槛；不得在实现后为了通过而静默上调。性能调查须记录并发负载；外部游戏或网络抖动不得当作可重复的本地性能证据。

## 15. CI 与执行节奏

Windows 固定 required jobs、工具链和托管 runner 遵守 [2.0.1 发布规范](release-2.0.1.md)。真实游戏手测由用户完成并单独记录，不属于 CI 或发布门禁。以下额外测试验证 CI/发布合同，模拟发布器用于离线故障测试，不在普通测试中向真实 registry 写入。

| ID | 级别 | 场景 | 必须观察到的结果 |
| --- | --- | --- | --- |
| REL-01 | P0 | package/lock/TOC/CLI/manifest 任一不是 2.0.1 | 正式版本门槛失败，禁止以 v2.0.1 发布 |
| REL-02 | P0 | 任一 Windows required job 失败、跳过或取消 | ci-required/release-gate 明确失败，不能由 Linux 通过抵消 |
| REL-03 | P0 | Windows 原生 exe 与实际 npm tgz | 在 Windows 隔离安装并执行，空格/中文路径和退出码正常 |
| REL-04 | P0 | 托管 runner 无交互桌面 | 不创建 self-hosted desktop job；游戏真机由用户人工验收并在实施状态单独记录，自动发行门禁不等待桌面 artifact |
| REL-05 | P0 | tag Commit 与测试/实机/产物 Commit 或摘要不同 | 拒绝发布，不能借用另一个 RC 的 passed 报告 |
| REL-06 | P0 | 验收后的 tgz 被修改或 publish 前重新 pack | 摘要校验失败；发布器只能消费封存的准确文件 |
| REL-07 | P0 | OIDC workflow/repo/environment 不匹配或认证失败 | 停止，不退到长效 token；dry-run 不具备真实发布路径 |
| REL-08 | P0 | npm 包有 optional/runtime 依赖或安装时下载 | 白名单检查失败；包内二进制齐全且 ignore-scripts 可运行 |
| REL-09 | P0 | registry 已有同版本、publish 超时或发布后暂不可见 | 区分存在/不存在/未知；已接受的 publish 只重试有界回读，不重复发布；仅在 integrity 相同时继续后验证 |
| REL-10 | P0 | npm 成功但 Release 创建失败 | Release job 必须具备 `GH_TOKEN` 和 `contents: write`；失败时只补后验证与 Release，不重复 publish 或移动 tag |
| REL-11 | P0 | RC 与正式版本渠道 | 2.0.1-rc.N 只进入 next，正式 2.0.1 进入 latest；不得先占用正式版试装 |
| REL-12 | P0 | 发布后 registry 回读与干净安装 | version/Commit/integrity/来源证明/资源一致，所有声明平台可运行 |
| REL-13 | P0 | 一个原生平台产物缺失或许可清单不完整 | 发行失败，不将缺失转换成 warning 后继续 |
| REL-14 | P1 | npm 聚合包压缩/解包体积和安装耗时 | 达到冻结门槛；不静默引入平台依赖改变分发合同 |

| 执行时机 | 内容 | 环境与门槛 |
| --- | --- | --- |
| 每个变更 | 格式、vet、契约、模块测试、离线 fixtures、Lua 四端、技能引用 | Windows 的适用子集；无真实账号与公网依赖 |
| 每个合并候选 | 真实 CLI 多进程、恢复故障矩阵、包安装 | 临时独立 workspace；P0 全过 |
| 每晚 | fuzz、重复交错种子、资源泄漏、固定性能 | 记录预算和种子；捕获机器与普通 runner 分开 |
| 发行候选 | 上述自动化检查 + Windows amd64 运行 smoke、真实网络与 skill 情景 | 游戏真机手测由用户完成并单独记载；自动 CI 只以可在托管 runner 稳定执行的检查为门禁 |

建议执行 `go test ./...`、`go vet ./...`，在受支持 runner 上执行 race；race 测试环境可能需要 CGO/工具链，与 CGO_ENABLED=0 的发行构建分别配置。fuzz 聚焦 SV、QR 信号、DB2/BLTE、SQL、TOC/XML 和协议状态，定时保存能复现的失败输入。

真实网络 smoke 绑定响应来源和时间；网络不可用归为 blocked。功能期望主要由离线固定 fixtures 保证，不能让变化的 CDN 数据决定普通 PR 是否“回归”。

## 16. 发布判定

发布报告必须列出全部 P0 的状态和证据位置，按能力列出 P1、平台及客户端支持。未完成测试写明 not_run/blocked，不能用总体通过率掩盖。

最终硬条件：新原生程序独立工作；旧命名和旧协议不构成依赖；不继承旧数据；新数据不会被清理误删；数据查询与实机任务可并行；同一窗口不串输入；不确定执行不自动重跑；完整报告、ACK 与清理准确；四端和发行验证与声明一致。

工作台 8 类能力任一未迁入或未按 11a 矩阵验收 → 不得发布。
