# Live 控制架构复审：统一决策与输入证据

状态：核心重构已落地到工作区，客户端验收按下方实测记录逐项认定。2026-09-28。
适用于当前原生内存 + 64 槽位分支；source/data、既有发布包和旧日志不在替换范围。
本页细化 [Live 总方案](live-memory-slot-plan.md)，实测事实仍以工作台审计为准。

## 结论

保留原生内存读取、64 个 LoD 槽位和项目日志。需要收敛的是控制架构。
输入框吞键、重连卡住、零输入被记作不确定执行，来自相同问题：
决策分散，输入观测、发送结果、游戏执行结果没有明确分层。

目标是一个编排模块负责推进，底层只提供事实。不能承诺操作系统、游戏和用户并发操作下
永不失败；可以验收不串实例、不盲重放、不伪成功，以及符合策略的任务自动续跑。

## 从本轮代码和实验得到的证据

| 现象 | 当前结构问题 | 架构要求 |
| --- | --- | --- |
| F12 仍被编辑框吞掉 | 把非字符键近似成可靠调用 | 发送只产生输入事实，接受必须由准确回执证明 |
| `inputBlocked` 参与多个条件分支 | 游戏焦点、系统按键、战斗、身份、输入保护混成一个门禁 | 保留原因和 unknown；就绪采样不是执行授权 |
| Esc 字段追加到 Slot Transaction | 输入恢复和业务协议交换共享一组可变阶段 | 输入尝试有独立证据，关联交换 ID，不改写业务执行阶段 |
| 重连时旧采样挤满命中上限 | 搜索器的原始命中预算影响协议发现 | 流式验证，限定有效结果；缓存和候选噪声不改变判定 |
| 采样后写日志、检查安装、再发键 | 磁盘/证据开销消耗了采样时效 | 动作意图先持久化；临近发键重新验证，厚重证据延后归档 |
| 系统按键已按住也进入 `input_attempted` | `Send() error` 丢失了发送数量和确定性 | 返回结构化发送事实；只有可靠的零发送证明允许再次尝试 |
| disconnect 原来仅推进一次 | 每个入口自行解释 pending 和等待 | connect/execute/reload/disconnect/resume 使用同一推进器 |
| 有待处理 unbind 时仍显示 `complete=true` | 结果映射用 Bound 或旧业务完成状态推导当前命令成功 | 当前请求、连接、业务结果和清理分别呈现 |
| 特殊测试模式帮助现场恢复 | 常规接口不能覆盖完整恢复路径 | 正式恢复通过公开入口；故障工具只制造故障、收集证据 |

以上是重构前的诊断依据。当前已移除 optional `inputPreparer`、可变 Driver/Reconcile
回调和 Native 内的 Esc 循环；连接后的所有入口都通过 `Driver.Continue` 推进。
Native 返回必需的领域观测和结构化发送结果，CLI 不再在命令层覆盖 reload 完成条件。

## 三个模块，只有一个决策者

```text
CLI / Skill
    ↓ 意图 + 固定目标 + 截止时间 + 恢复策略
会话编排模块 ── 项目日志 / 输入尝试 / 结果文件
    ↓ 已落盘的动作                 ↑ 类型明确的事实
本机传输模块：内存观测、槽位文件、单次按键、受管安装
    ↕ 内存记录 + LoD 槽位
游戏执行模块：身份、owner、协议校验、执行、结果、活动显示
```

### 会话编排模块

- 这是唯一允许推进持久状态、安排重试或决定 reload 的模块。
- 对外沿用 connect、execute、resume、reload、disconnect 等产品意图；
  Agent 不需要选槽位、猜 Esc 次数或理解协议阶段。
- 一个推进器消费当前状态和新事实，决定一个动作。动作意图落盘之后，才调用传输。
  动作结果也落盘；退出后从这条证据链继续。无需引入消息总线、后台守护进程或调度框架。

### 游戏进程退出后的连接收尾

`live disconnect <CON>` 在打开内存通道前核验固定 PID 和进程创建时间。
只有 OS 证实进程退出、PID 不存在或已复用，才允许无游戏输入的资源收尾；
窗口消失、权限不足、暂时无法扫描均不构成退出证据。
收尾持有原连接执行锁，再次核验进程身份，先追加 `process_end_observed`（含原事务），
再在发布锁内退役该连接确切 consumer/runtime/nonce 的槽位，最后记录 closed 并释放确切 owner。
发布中断可按现存受管 payload 的已知 hash 收敛；不伪造 consumed 或 ACK。
已确认报告保持可用，清理标为 runtime_destroyed；其余操作保留 execution_unknown/unavailable。
closed 不等于业务 complete。崩溃后的同一 disconnect 可重复收尾，不能把旧连接迁到新进程。
- 同一请求键和内容绑定，重复调用返回原进度或结果。跨 runtime 恢复沿用业务 ID，
  新 attempt 单独记录，不覆盖旧 nonce、执行不确定性或失败证据。
- 连接、业务操作、协议交换、输入尝试是不同对象。它们有明确归属，不做四套彼此独立的调度器。

### 本机传输模块

- 执行已决定的一次动作，返回事实。不得自行开始新业务、换角色、刷新 nonce 或代替编排决定重放。
- 对编排提供领域观测：候选身份、输入观测、准确回执、已校验结果。
  原始地址、扫描分区、缓存、校验和细节留在模块内部。
- 系统输入统一返回 `not_sent / submitted / uncertain`，附排队消息数和错误原因。
  `submitted` 只表示消息入队；不表示游戏收到，更不表示执行成功。
- 原生 Windows adapter 与离线故障 adapter 使用相同接口。输入观测是必需契约，
  不通过可选类型断言使测试悄悄绕过生产门禁。
- 部署资格、固定 PID/进程创建时间和跨进程输入互斥集中检查；扫描时不长期占输入锁。

### 游戏执行模块

- 执行时重新核对 runtime、owner/fence、角色/build、slot、nonce、challenge；
  对外部输入观测不作授权依赖。先更新协议状态，再发布对应事实。
- 接收、执行、结果保留、输入保护分开。活动视图只消费状态，不能通过显示/隐藏控制执行或持有键鼠。
- 普通查询和异步探针不锁输入。短暂输入保护、显式 UI 保护按现有策略独立释放。
- 保留顶左荔枝及“Agent 运行中 / Agent 接管中”。输入恢复不增加色块；
  原有 reload 提示只是提示，不能证明 runtime 或请求完成。

## 输入恢复作为统一流程的一部分

逻辑顺序是：确认目标及归属 → 观察 → 如有普通焦点阻挡，落盘单次 Esc 意图 →
发送前复核 → 发一个 Esc → 读取新采样 → 再决定。直到可调用或截止时间到达。

| 观测 | 下一步 |
| --- | --- |
| 普通编辑框占焦点 | 单次 Esc；允许原界面关闭/取消，随后重新观察 |
| 没有焦点阻挡且其他条件满足 | 调用当前已发布槽位，等待准确回执 |
| 系统相关按键已按住 | 不抢占用户按键；等待，可靠零发送时可继续原尝试 |
| 战斗、保护阶段不允许输入 | 等待原因解除，不发送 Esc |
| 采样缺失/过期/secret/API 不可用 | unknown；不能解释为 false，也不能凭空发送 Esc |
| PID、进程创建时间、owner 或角色不符 | 停止当前输入，保留证据；禁止静默切目标 |
| runtime 改变 | 转入统一恢复流程，先重建准确绑定，再按业务策略续跑 |
| 截止时间到达 | 返回可恢复的等待状态、原因及准确连接 ID；不新开连接 |

用户没有要求固定 Esc 次数上限。次数由新鲜观测和命令 deadline 限制；
没有进展也不得绕过 deadline。任意键盘拦截器未必能由 GetCurrentKeyBoardFocus 发现，
因此 `inputBlocked=false` 不保证快捷键会被游戏处理。回执仍是必需步骤。

发送前意图落盘与临近发送的复核都必须存在。复核需要完整扫描时应先释放输入锁；
可在锁内快速重读已发现记录，但地址只是提示，必须重新校验身份、记录和时效。
重读失败回到正常发现，不把缓存提升为正确性前提。

当前实现用 GetTime / Windows uptime 约束样本新鲜度。该时基关系需要按客户端能力明确验证，
不能从一个 Retail 实验推断所有 build。原固定等待 200 ms 已移除；推进器的退避只是调度措施，不能作为正确性证明。
后台低帧率、时钟偏差和长停顿必须有离线及实机用例；不能靠放宽时间窗口掩盖。

## 安装、reload、多实例与续跑共用规则

1. 干净受管安装、磁盘版本正确、64 槽位完整、游戏已加载该版本、连接已验证，分别记录。
2. 首装尚无内存状态时只能走已定义、已记账的安装激活路径；不能把缺状态当成就绪。
   用户显式关闭桥时不得以无限 Esc 或后台唤醒偷偷重新启用。
3. 每个进程实例只允许一个 owner；同一安装目录的槽位发布另有互斥。
   build/角色来自运行时观测，不能从目录名推断。
4. reload 后丢弃旧输入资格和裸地址可信度。新 runtime 必须完成准确绑定，
   才能判断旧运行已结束；色块、超时或旧 heap 记录均不能替代。
5. 已核验并持久化结果的任务只补清理。未提交执行的任务可以继续。
   不确定的 observation 按既有策略建立新 attempt；不透明副作用任务不盲目重放。
6. 日志丢失走显式恢复入口，保留机器级占用和游戏 owner，不能直接另开连接覆盖。
   “可续跑”不等于在证据丢失后猜测执行结果。

### Reload 的输入选择

连接内 reload 与 invoke 共用输入观测/单次 Esc 决策。就绪后只发 Enter、`/reload`、Enter，
没有固定 Esc 前缀。插件身份的 `inputState: lycheedev.input.v1` 表示支持观测；
显式 `live reload fallback` 发现该能力时也直接建立同一推进器的 reload 意图。
支持观测但状态缺失/过期时保持 pending，不能静默切换为盲发。

仅首装或没有该能力的旧 runtime 使用一次已记账的 Esc×3 兜底序列。发送中断后的未知结果
不会重放。两条路径最后都必须发现新 runtime 并完成新绑定；发送完 `/reload` 不是成功。
系统与用户可在观测后改变输入路由，所以就绪不是聊天输入或快捷键必然生效的承诺。

## 日志、结果与状态呈现

- 一个日志写入者；副作用前记录意图，之后记录事实。崩溃夹在两者之间一律未知，
  即使上一次进程可能根本没来得及发键，也不能当作可靠零发送。
- 代码与结果单独按内容摘要保存，输入尝试引用它们，避免每个 Esc 重复写整段脚本。
- 高频输入采样不逐条持久化；只保留决策所依据的采样和实际尝试。
- 扫描提前找到结果时保留覆盖摘要；未扫描范围与真实读失败缺口分别表达，
  不给每个未扫描块生成庞大的重复错误记录。证据有字节与数量预算。
- 当前命令完成条件由同一编排模块给出。已连接不代表 disconnect 完成；
  上个探针成功不代表本次 reload 完成。UI/CLI/Skill 只呈现事实，不再另写推导分支。
- 输入保护与业务结果分开；红色只表示业务失败。ACK/结果已收取属于传输事实。

## 实施顺序与替换要求

1. 冻结目标、事实类型、完成条件和恢复表；把当前复现用例作为接口验收。
2. 先统一发送事实与动作日志，再替换单一推进器；移除可选 inputPreparer 和隐式 Reconcile 改状态回调。
3. 收拢内存观测、输入、文件发布的底层细节；所有公开 live 入口使用同一推进器。
4. 迁移现有日志保持可读，不能重解释旧 input_attempted 为零发送；协议有变化时显式升级。
5. 收敛游戏端状态所有权及 UI 投影，删除旧的平行推进入口。
6. 离线故障矩阵通过后，才进行各客户端真机、缓存开关、reload 与多实例验收。

这不是要求先增加一层包装再保留所有旧调用路径。每迁完一项，删除被替换的决策分支；
测试调用与产品相同接口。能持续通过的旧协议、扫描和 Lua 测试继续保留，
仅断言内部实现形状的测试随结构替换，不叠加两套行为契约。

## 验收门槛

- 对每个副作用，在意图前、意图后、实际输入后、事实落盘前、回执后分别崩溃并恢复。
- 零发送可以继续同槽位；部分/未知发送不重发；已接受任务不能重复执行业务。
- 输入框需 0/1/3/N 次 Esc、Esc 无效果、焦点反复变化、按键被占用、战斗与 unknown。
- 大量旧采样、旧 run、旧 BODY、采样跨块、低帧率、时钟偏差；缓存失效与禁用得到相同判定。
- 首装/升级/显式关闭桥、用户 reload、运行中 reload、进程退出、角色变化、槽位耗尽。
- 同实例两个项目争用、两个不同实例、共享安装的两个进程；任何等待均不能串窗。
- disconnect/reload/execute 途中等待，当前命令不得误报 complete；结果成功与清理 pending 分开。
- 测试正常与异常退出后，输入锁、注入修饰键和游戏保护状态均有可核验的释放结果。
- 无状态扫描、证据体积、最坏内存使用及单次推进耗时单独测量；未命中不能只用平均耗时掩盖。
- 实机基准只使用公开 CLI 完成恢复；不依赖测试专用解锁、手改日志或隐式选另一窗口。

所有客户端与故障矩阵齐备前，不把核心实现完成等同于全矩阵验收。

## 实现索引

- `internal/live/channel/wait.go`：唯一连接推进循环；`reload.go`、`recovery.go` 是其状态步骤。
- `input.go`：独立输入意图、事实和就绪决策；已知事实在取消后仍有有界落盘机会。
- `input_windows.go`：单次物理动作，发键前快速复核；不在输入锁内完整扫描。
- `observations.go`：回执与 HEAD/BODY 关联验证；原始地址不进入业务状态。
- `artifacts.go`：代码与结果按 SHA-256 保存一次，日志保存引用；旧内联快照仍可读。
  整个 `.lycheedev/live` 是恢复单元，缺失/损坏内容不允许重新执行。旧 CLI 不支持新引用格式，
  因而不能用旧 CLI 恢复新日志。
- `memory/scan.go`：提前找到准确结果时保留 `stoppedEarly` 和覆盖统计，未扫描块不伪装成读失败。
- `skills/lycheedev`：入口选择任务，引用文档解释观察、恢复、reload 与证据保留。
