## Real pressure capability remains a candidate

Data native availability is the minimum of GlobalMemoryStatusEx available physical/pagefile/virtual values. [Microsoft MEMORYSTATUSEX](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/ns-sysinfoapi-memorystatusex) describes current-process commit allowance; [nested Jobs](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs) constrain effective limits, but actual selected Job-chain mapping still needs bounded observation.

Existing owned Node process helper sets kill-on-close, not a memory-cap option. Existing native guarded-spawn/Job primitives are possible building blocks; no installed-Skill pressure harness is currently connected. A minimal future test must observe actual child Job limit/native headroom, retain safe startup/error-reporting margin, then cause a normal budget rejection at the existing64MiB logical SQL executor reservation after admission, fully retire/reap, remove the isolated constraint and succeed with the same pin. No existing ready command emits both the controlled child Job cap and production native availability; a narrow test-only observation helper is the missing prerequisite. No host-memory exhaustion, guessed cap, system setting changes or budget relaxation. A kill/timeout is not a successful budget rejection. Current observer fixtures and tiny successful Skill inputs do not close this gap. There is no new runtime pressure result here.
