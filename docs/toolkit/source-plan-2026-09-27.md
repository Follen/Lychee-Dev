命令已经存在；公共命令仍以 `describe` 为准。现有 data 优化和未提交代码不受影响。

## 1. 推荐决策

采用 **Go 原生事实索引 + 按需 LuaLS 深度分析 + 统一 WoW 语义和证据**。

- 保留 gopher-lua 作为当前 Lua 语法解析基线，XML 使用 Go 标准库，TOC 由
  Lychee 处理。先合并重复的事实提取，不自行扩建完整 Lua 类型系统。
- LuaLS 是拟引入的唯一高级语义分析后端。通过稳定 CLI/LSP 接口使用，不绑定
  内部 AST/VM 接口，不 fork 一份长期维护的语言服务器。
- Tree-sitter 暂不进入产品默认依赖。若真实失败样本证明当前 parser 的容错或
  源码范围限制成为瓶颈，再做替换试验。它不能替代 LuaLS 的语义分析。
- 公共查询、搜索、SQL 和差异分析以自己的版本化事实为输入；外部工具输出
  经适配、标注覆盖与来源后入库，不直接作为我们的公共数据模型。
- 用户安装一个包、调用一个 CLI。重分析能力按场景自动选择，用户不必选择
  parser 或手工配置语言服务器。自动选择不等于失败后静默降低验证范围。

这是在当前 Windows amd64、Go CLI、npm 分发和固定证据约束下的推荐方案。
LuaLS 的净收益尚需原型实测；进入发行的条件见第 7 节。

## 2. 从使用场景决定执行成本

| 场景 | 默认执行路径 | 交付结果 |
| --- | --- | --- |
| 查 API、事件、模板或一段源码 | 固定 source pin → 原生索引 → 有界上下文 | 结构化定义、原文、关系候选、位置、版本与覆盖 |
| 研究 Blizzard 或第三方插件实现 | 正文/符号检索 → 确认候选 → 按需引用分析 | 调用或引用位置、加载来源、确定/推断/未知关系 |
| 检查本地正在开发的插件 | 冻结 TOC 闭包 → 原生加载检查 → LuaLS → WoW 规则 | 按文件定位的诊断、规则依据和未检查项 |
| 迁移客户端或插件版本 | 两个固定 API/源码合同 → 差异 → 本地用法关联 | 受影响调用点、变化类别、需改与需核验项 |
| 调查一个游戏功能 | source、data 各自固定身份 → 引用关联 → 授权范围内 live | 源码依据、数据记录与运行态观察分别标注 |
| 多 Agent/重复查询 | 显式固定引用 → 共享不可变索引及分析产物 | 同一版本、同一证据，不重复建索引或重跑分析 |

普通检索不启动 LuaLS。深度分析先复用兼容的已完成产物；未命中时启动一个受控
任务。一个任务可批量完成多个 LSP 请求，结束后关闭进程，不建设常驻后台服务。
CLI-only diagnostics 与 LSP definition/references 是不同能力，不能把 `--check`
报告当成完整引用数据库；缺失能力应明确记录。

## 3. 数据和模块分工

处理链为：

```text
固定远程 commit / 本地内容快照
              │
    TOC/XML 闭包与客户端身份
              │
      原生解析与内容缓存
              │
      统一 WoW 事实模型 ← 按需 LuaLS 分析
              │
    索引 / 搜索 / SQL / 版本影响分析
              │
    固定证据 + 有界结果 + Agent 后续动作
```

事实模型分为文件、符号、API 参数/返回值、关系、加载关系和诊断。此处为拟议逻辑
模型，不直接开放内部 SQLite 表。符号身份包含文件/作用域/声明位置，不能只用
名称；关系记录来源分析器、配置摘要、确定性与支持证据。

WoW 语义由同一个模块维护：客户端目录身份、TOC 加载和依赖、XML 模板、Mixin、
事件以及固定 API 基线。索引、校验和迁移分析共用这些事实。通用语言工具负责
语言能力；WoW 模块负责解释这些能力在所选客户端和加载上下文里的适用范围。

每次本地分析先保存文件内容摘要和闭包清单，再基于冻结副本执行，不能读取到
用户编辑前后的混合版本。LuaLS 输入只包含选中闭包和显式声明的库；未满足的
依赖列为缺失，不把 AddOns 整个目录或其他客户端文件混进分析。

从固定 Blizzard API 描述生成同版本 LuaLS definition files，并为有依据的
XML/Mixin/全局环境生成可追溯声明。生成不出的部分保留 unknown，不能用统一
的 `any` 或无限全局白名单掩盖缺失。声明存在不证明运行态一定可用。

LuaLS 配置由 Toolkit 生成并固定；不自动加载被研究仓库的可执行 Lua 配置、
运行时插件或第三方自动发现配置。分析不执行目标插件代码。报告保留文件映射，
让用户看到原始插件位置，而不是冻结副本或生成声明的内部路径。

## 4. 查询、性能和 SQL

### 搜索与上下文

保留精确符号优先，增加正文/文档检索和标识符分词；验证当前 SQLite 构建的
FTS 能力后再确定具体索引实现，不继续把子串匹配标成真正的全文索引。
索引准备在已固定 pin 下自动完成；明确的离线/只读约束仍优先，不允许换版本。

结果可组合定义、必要原文、直接引用、事件和加载来源，并按字节/条数预算输出。
每项位置可单独追溯。只缺后半段结果时返回稳定 cursor，不要求 Agent 换词绕过
截断。cursor 绑定 snapshot、query、排序、schema 和内容身份；修改条件后拒绝续页。

### 缓存和增量

- 文件事实缓存按内容摘要、文件种类/影响解析的上下文和 parser 版本区分；
  路径相关身份在组装索引时重绑定，不能让重命名复用错误位置。
- 新 commit 复用不变文件的事实，只解析变化文件；索引仍整体原子发布。
- 深度分析缓存另外绑定完整加载闭包、所有依赖、客户端定义、LuaLS 版本和配置。
  只改一个文件也必须正确失效受影响语义结果；第一版可重新分析闭包，不能以
  不可靠的跨文件增量换速度。
- schema/parser/engine 升级保留旧 capture 可读性；新结果重新计算，不能覆盖旧证据。

测量同步、读取、解析、建索引、分析器启动/执行、查询和序列化成本，以及实际
读取/解析文件数、命中率、输出字节和峰值内存。完整任务耗时优先于 parser 单项跑分。

### SQL

让 source 事实通过只读 adapter 接入现有关系查询引擎，保留参数、JOIN、预算、
EXPLAIN 和不完整传播。原有 data 命令和静态查询语义保持不变；不另写 source
SQL 引擎，也不强迫简单的符号查询必须先写 SQL。

第一批可支持 API、参数、用法和加载关系之间的查询。跨 source/data 的关联需要
显式 source commit、data build 和已证明的关联字段。数值字面量不能自动当作
spellID；SQL 零行结果也不能消除上游 unknown 或 incomplete。

## 5. 覆盖状态与错误合同

分别表达准备状态、解析覆盖、语义覆盖、结果分页以及诊断结论。发现真实错误
与分析未完成是两个维度：完整检查可以发现错误，零条错误也可能检查不完整。

每条诊断保留 engine/version、rule、位置、客户端和证据。WoW 与 LuaLS 诊断可
去重，但不抹去来源；冲突必须可见。动态调用、不满足的加载依赖、分析器超时
和不支持的客户端保留明确原因。

显式请求深度验证而分析器不可用时，返回已得到的基础结果和未完成状态，按
已有能力/环境错误约定处理；不能悄悄返回“验证通过”。纯静态结果不能证明
secret 值、战斗保护、taint 或实际游戏表现安全。

同一任务涉及 live 时仍沿用既有授权和 finish 合同。源码/数据研究不会自动获得
发送游戏输入的权限，也不为了完整报告而创建无必要的实时会话。

## 6. 分发与依赖决策

推荐最终在现有单 npm 包和 Windows 压缩包里携带一个固定版本的 LuaLS 私有
工具目录，由 CLI 定位并按需启动。用户不额外安装 Node 库、Lua、编辑器或
语言服务器，不需要等待首次使用联网下载。Go 主程序继续维持 CGO_ENABLED=0。

这是拟议的发行合同调整：从只有 Go 主程序的运行载荷扩展为主程序加一个受管
分析器目录；npm 无运行时包依赖不等于没有辅助进程。落地时必须同步设计、
工具清单、许可清单、digest、doctor 和安装验收，不能宣称发行构成完全没变。

固定并验证整个 LuaLS 运行目录及需要的资源，测试离线、带空格/中文路径、
普通用户权限、取消和异常退出。只在调用对应能力时启动；版本混用不得被静默
接受。发布前测量包体积、启动和内存成本。尚未选择或验证具体 LuaLS release。

Tree-sitter 默认延期：目前快照查询不依赖逐键增量编辑，优先收益来自内容级
复用、检索和成熟语义分析。将来若替换 parser，应通过同一事实模型适配并单独
评估 C/CGO 或其他运行载荷的成本，避免为了通用性同时常驻多套引擎。

## 7. 实施顺序与可交付门槛

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| A：基线与 LuaLS 原型 | 固定样本、真实耗时基线；隔离分析目录；CLI 诊断和少量 LSP 定义/引用请求 | 证明别名、作用域、跨文件引用的增益；记录误报、未解析、启动/内存/包体积。未证明收益不进入默认发行 |
| B：统一事实和索引 | 共用提取结果、API 结构化合同、内容缓存、本地冻结快照、覆盖拆分 | 原有 source 回归保持；重命名/作用域/解析错误/跨客户端不串结果；新 commit 只重新解析变化内容 |
| C：搜索与研究流程 | 正文检索、稳定续页、有界上下文、同 pin 自动准备、结构化后续动作 | 固定研究任务命中正确原文；完整续页无重复/漏项；Agent 不停在建索引阶段 |
| D：WoW 深度分析 | 固定定义生成、LuaLS 适配、闭包和依赖建模、诊断合并 | API 别名、同名局部函数、事件、Mixin、XML 脚本、动态调用和受限环境样本；错误与 unknown 分开 |
| E：迁移和 SQL | API 合同差异、用法影响定位、只读 source adapter、显式跨域关联 | 区分移动/新增/移除/合同变化；重复声明保留；SQL NULL/精确数值/预算/partial 不回归 |
| F：发行与 Agent 验收 | 单包私有分析器、文档/命令契约/skill、Windows 安装验证 | 普通查询不启动 LuaLS；离线能力与声明相符；取消无残留任务；完整任务证据可复现 |

原型通过后推荐完整实施 B–F。若 A 证明 LuaLS 对真实 WoW 工作负载收益不足，
保留 B/C 等独立收益，记录失败原因，再选择语义后端；不得把尚未验证的工具
依赖作为不可撤回的前提。

测试矩阵包括固定的 Retail/Classic/Titan 基线、Blizzard/第三方插件样本和
本地 addon 加载闭包。Forever 继续保持当前未验收状态。小型人工可核对样本
作为语义正确性依据，工具互相一致只能提供补充信心。

性能采用同机器、同样本、重复测量的基线比较：普通热查询 p95 不应出现有意义
回退；必须报告实际重解析文件数。Agent 验收记录调用次数、读取字节、总耗时、
结论正确性和是否完整收尾。绝对时间/内存上限在 A 阶段实测后定，不预先承诺
未经测量的倍数。只改文档的本次提案不声称完成以上任何验收。
