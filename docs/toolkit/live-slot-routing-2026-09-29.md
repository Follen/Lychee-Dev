# 200 槽与共享安装的前向分配

本页是 native CON 槽位部分的当前合同，替代旧 64 槽文档中的固定 nextSlot 发布规则。
三色块、内存读取、实例所有权、短发布锁、prepare/commit 和持久预算保持原合同。
本次候选未发布；实机验证结果独立记录，离线测试不等于实机通过。

## 分配与执行

- 新运行时、封套与槽池采用 200 槽 v2；身份记录继续使用 identity.v1，slots 明确标识容量。
- 游戏内 nextSlot 是此运行时尚未加载的第一个 LoD；CLI 把它保存为 startSlot。
  物理 index 可以更大，但 startSlot、runtime、owner、nonce 不随跳槽改变。
- 仅发布函数确认原槽属于另一未决预约、且本交换没有输入尝试时，Driver 才能改选后方空槽。
  先保存新 index，再尝试发布；分配竞态重新经过相同检查，最多走到 200。
  已发布、部分/未知输入或已有回执的交换不能通过跳槽补发。
- 发键前持有短发布锁，核验全部受管文件及目标准确预约，再检查实际路径内容。
  已开始但未完成的文件替换可能还保留旧 payload，不能用账本的 consumer 代替实际字节。
  输入内存样本必须精确对应原 startSlot，并在发键前再次读取；不能仅放宽成 nextSlot <= index。
- 一次唤醒顺序加载空内容或严格有效的其他 runtime 封套；每个已加载 LoD 仅在本运行时标为消耗。
  不对其他 runtime 发布消费回执，也不释放其磁盘预约。遇到本 runtime 的第一个封套立即停止，
  包括拒绝、旧 nonce、owner 不符。畸形内容或 loader 未回调同样停止。
- Lua 最多加载 200 个槽，nextSlot 使用单调游标。加载和执行都来自原唤醒事件，没有常驻扫描器。
  延迟唤醒仍可能消耗槽位；它不是重发未知输入的理由，业务执行仍须准确 prepare/commit challenge。

## 容量与兼容

新运行时保留最多 46 个操作身份，正常任务在 nextSlot > 185 时由现有协调器执行容量 reload。
CLI 不把不够留下 commit/confirm/release/unbind 空间的尾部槽分配给新的 prepare。
所有前向可用槽被预约时返回 slot_pool_full / forward_slot_available，保持原事务及剩余预算。
这是有限资源背压，不承诺无限并发或故障情况下完全无等待。

200 个 LoD 不会在禁用状态自行加载；原有 opt-in 与输入采样预算保持不变。
跳过多个槽增加当次按键事件中的同步加载开销，上界由 200 固定，实机耗时需独立测量。

旧 64 槽池与 v1 日志支持原槽恢复/收尾，不能混用 v2 封套或跳槽语义。
受管迁移要求无未决预约，检查全部原文件及新目录，先保存旧 CLI 无法接管的迁移意图，
最后原子提交 200 槽账本；中断可继续，不能收养未知目录或清掉未知预约。
每个在线 PID 必须分别激活并证明 inventory=200；磁盘更新不证明运行时或客户端目录缓存已更新。
新连接发现旧 64 槽运行时会走记录在案的激活；reload 后目录仍不足则明确要求重启客户端。

## 验收范围

离线包含 Lua 四客户端 profile 的空槽/foreign 跳过、本 runtime 拒绝停止、200 边界，
Go 真实发布/日志恢复、原槽字节与预约保留、精确输入起点、64→200 中断迁移及版本隔离。
正式服双实例需另验：A 已发布未发键时 B 跳过、A 原请求恢复、重复请求只读、两实例结果身份一致、
并发输入互斥、容量换代、断开后预约/owner 清零。未执行项继续标记 not_run。

Skill 仅使用公开 CLI 的 continuation 编排固定 CON/PID，不选择槽号、不修改封套、不续长预算。
