# 输入状态 1 秒采样影响调研

历史记录：本文记录实施前的只读调研，以下测试与当时源码状态不作追溯改写。
后续获授权的 1s 实现及验证状态见[实施记录](input-cadence-implementation-2026-09-29.md)。

用户最新方向为保留常驻采样，评估从 100ms 调至 1s。本轮没有更改生产 addon 的采样周期，
也没有部署新 addon 或操作游戏。此前开发中的按需唤醒/短窗口方案已撤回；其工作副本仅留在
`.tmp/input-cadence-20260929/bounded-telemetry-wip.patch`，不是当前实现。

## 结论

1s 可以减少状态读取、序列化和字符串分配，但不能只改一个常量就认为业务无影响。
必须保留现有 500ms 新鲜性、目标身份和发送前原地址复核，并处理“样本正常过期”与
“运行时真正失联”的区别，避免自然等待触发全进程扫描。是否可接受延迟仍需配套改动后实测。

## 可重复的离线证据

证据目录 `.tmp/input-cadence-20260929/`：

- `cadence_sampler.lua` 载入真实 Lua 5.1 InputState/CaptureWriter/MemoryProtocol，
  仅在内存中的模块源码将周期改为 1s；模拟 30/60/144 FPS 各 60 秒，未修改生产文件。
  `sampler-results.txt`：100ms 模式分别生成 601/515/577 份样本，1s 为 59/61/60 份
  （均含首次即时样本）。采样/编码次数减少约 88–90%；两种模式 OnUpdate 调用次数均为
  1800/3600/8640。不是游戏 CPU 或帧率性能测试，不能宣称总 CPU 减少 90%。
- `cadence_research_test.go` 通过 Go overlay 调用生产 `inputObservation`，逐毫秒遍历
  理想采样相位。`gate-results.txt` 中，100ms 周期无处理耗时时 100/100 相位有效，
  1s 为 501/1000；保留同一已选样本并增加 300ms 处理时间后，分别为 100/100 与
  201/1000。错误角色全部拒绝。比例是理想相位模型，不是实机成功率。
- 同一模型下，输入后要求样本至少晚 100ms：100ms 周期理论等待 100–199ms，均值
  149.5ms；1s 为 100–1099ms，均值 599.5ms。不含按键发送、帧率、扫描和主机 250ms
  等待间隔。实际低帧率下周期还会偏长。

## 业务影响及原因

| 路径 | 1s 的影响 |
| --- | --- |
| 首连/重新绑定、prepare/commit/release 后 | owner/fence/nextSlot 改变后须等待新样本；理想均匀相位平均约等 0.5 秒，原约 0.05 秒 |
| 焦点恢复的逐次 ESC | 每次必须读到晚于上次输入至少 100ms 的样本；不能连发 ESC，理论平均额外约 450ms/轮 |
| reload | reload 前输入门禁及新 runtime 的后续绑定可能更慢；不能使用旧 runtime 样本 |
| 探针本身与报告 | 不改变 Lua 探针预算、异步任务语义或报告正确性；前后的传输阶段可能更慢 |
| 输入保护 | 有独立释放路径/期限；不应把采样间隔当作延长抢焦点或输入保护的理由 |
| 安全性 | 保留 500ms 时旧状态仍被拒绝；把有效期一同放宽到 1–2s 会增加误用过时焦点/战斗状态的窗口，不建议 |

当前放大路径：`ObserveInput` 的 selector.Accept 过滤过期样本 → hints 点读失败后
`memory.Find` 全扫 → 无结果为 `input_observation_unavailable` → `Continue` 可能继续
`RuntimeCandidate` 全身份扫描。已有 `input_observation_stale` 仅覆盖“查找时新鲜、返回时
才过期”，没有覆盖查询开始时自然过期的情况。此前实机单次完整扫描约数秒至十余秒；
不能把 1s 的影响简单说成最多慢一秒。

较小的配套方向是对“结构和目标正确、仅时间不够新”作短暂、有界的等待；
不要立即升级全扫描，也不能无限相信旧记录而漏掉真正 reload。首连和 runtime 换代
仍保留完整发现与挑战验证。该配套方向尚未实现或实机验证。

## 已授权内部优化 1–3 的当前状态

保留在当前工作树，公开命令、采样周期及输入授权规则不变：

1. 已知 runtime 的 hints 点读先验证进程/地址，不再先枚举整个区域表；完整发现不走捷径。
2. 全扫描在现有缓冲中有界学习最多 64 个已校验小记录地址，不保存 payload，不收集
   BODY，不构成输入授权；chunk 预筛无关候选，命中后停止无用分发和页面补读。
3. 最多 256 条查找诊断延后到命令收尾，以统一 10 秒预算落盘；Hints 合并一次保存。
   权威输入意图和回执日志仍在原位置。正常返回传播落盘失败；强杀进程可能丢失尚未
   写出的诊断，不能将这部分诊断宣称为 crash-durable。

计数回归：warm hints 区域枚举从 1 次降为 0，仍执行两次源读取和前后身份验证；
旁路地址复用也不再重扫。定向 tests/build/vet 已通过；本批完整离线结果以
`.tmp/input-cadence-20260929/offline/report.json` 为准。之前 14 组实机验收属于旧候选，
不自动覆盖本批内部优化。本文件在完整离线基准前保存。
