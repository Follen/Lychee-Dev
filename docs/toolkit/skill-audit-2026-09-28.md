## Scenario review

| User intent | Expected orchestration and boundary |
| --- | --- |
| Exact API/addon version | Resolve its exact ref, retain commit, inspect original source; no live discovery needed |
| References/secret-value hypothesis | Query stable symbol ID, preserve semantic/static/unknown boundaries; use bounded live evidence only within authorization |
| Full Hotfix query | Archive the original cache, scan/resume same snapshot and filters, distinguish unread pages, missing keys and no payload |
| SQL with overlays | Explicit raw captures and effective table qualification; preserve missing-key coverage in aggregates |
| Export texture | Resolve/inspect candidate ID, explicit encoding and destination; partial input does not become a complete artifact |
| Static compatibility | Validate actual TOC closure and fixed per-client environment; no claim of runtime or taint safety |
| New live connection or install activation | Resolve target identity, retain BTP/OP recovery; continue task instead of stopping at a QR |
| Complete live question | Stable request and immutable budget through execute; inspect business result separately from verified report and cleanup |
| Pending/unknown input | Inspect/resume exact owner; no retargeting, guessed chords, new request or automatic abandonment |
| Bugs/performance | Bounded existing provider or question-specific observation, explicit measurement scope, resource cleanup and finish |
| Update | Installed help first, explicit targets for isolation, pinned package/target recovery, filesystem versus runtime activation separated |

Automated checks validate syntax, paths, command/flag compatibility and real
mechanical outcomes. They do not establish that every future Agent prompt will
choose the intended route. No independent Agent forward-test or additional game
acceptance is claimed by this audit.
