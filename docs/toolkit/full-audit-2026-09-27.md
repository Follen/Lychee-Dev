## Findings and disposition

1. **P2, viewport fit — implemented in source; real-client check open.** `addon/UI/Window.lua` now fits the frame to the effective `UIParent` dimensions, provides bounded horizontal/vertical page scrolling and scrollable tab navigation, and adapts the Settings column. `tests/addon/t_visual.lua` checks 700×600 and 500×480 fixture viewports, tab access and Settings overflow. These offline checks retire the old source-level implementation gap. Real-client clipping, UI scale and long English copy still need visual evidence.

2. **P2, stale Settings bindings — implemented in source; real-client check open.** Reopening a cached Settings page now calls `RefreshBindingFields`, rereads the effective receiver profile and preserves locally edited draft text. `tests/addon/t_visual.lua` exercises an external binding change followed by reopen, retained draft and reset. This retires the old source-level finding. A real-client `/dev receiver bind`/reset and Settings interaction remains `not_run`.

3. **P1, source validation scaling — fixed in source during this audit.** The real-pin `source validate` call ran for several minutes with one Go process consuming CPU and no LuaLS child (the baseline process accumulated 268 CPU seconds; exact wall time was not recorded). The exact path `AssessAddon → CheckClosure → referenceSites` (`internal/codebase/check.go`) rescanned the complete 4,036-document pinned index for each distinct addon reference. The parallel legacy TOC compatibility path (`compat.go`) had the same pattern. Both now collect requested names and scan once, preserving category rules, match bounds, missing/unknown distinctions and per-use evidence. Deterministic many-name tests assert one scan; existing CheckClosure/ValidateTOC and the complete `internal/codebase` package tests pass. The rebuilt binary completed the same pinned addon validation in 1.5984892 seconds with an OK result (`.tmp/full-audit-source-20260927/source-addon-fixed-timing.json`). The addon files were changing during UI work, so this is a real-input speed check rather than a controlled exact-factor benchmark.

4. **P2, incorrect CLI warning — fixed in source during this audit.** The earlier `internal/command/entry.go` warning claimed `live bind` sent no input, while `internal/live/bind_window.go:53-58,65-80` sends a journaled, nonce-correlated `/dev bridge identify` transaction. The live code owner changed the warning to state that identity input is sent but business work is not (`entry.go:368`). Recheck emitted output in the affected command test. This audit did not edit that production code.

5. **P2, stale skill facts — corrected here.** `skills/lycheedev/references/data-investigation.md` previously said only static SQL tables exist and no Hotfix overlay is possible. The command contract and `data-query-recipes.md` support explicit `effective.Table` with raw cache captures in query JSON. `skills/lycheedev/references/asset-export.md` previously said there was no decryption key provider and that local asset inspect never uses network. Both references now describe the actual opt-in behavior and limits. The command reference was regenerated from `describe`, not manually edited; `skill-contract --check` passes (84 commands, 226 references, zero violations).
