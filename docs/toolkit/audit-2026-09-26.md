## 二维码设计与证据

`TestOpticalPairRetainsProofsAndReducesArea` 使用生产 Lua CaptureWriter 和
MatrixSymbol 对交接中的 Classic 载荷计算尺寸，保持模块为 3 UI 单位：

| 显示 | 尺寸（UI 单位） | 面积 |
| --- | --- | --- |
| 原双码上下排列 | 219 × 426 | 93,294 |
| 单码封装 | 255 × 255 | 65,025 |

高度减少 40.1%，面积减少 30.3%，宽度增加 16.4%。封装为 372 字节 UTF-8 JSON。
没有压缩、轮播、额外游戏输入或后台轮询。readiness 不覆盖报告的 inputReady，
也不改变报告序号：它有独立 nonce、更新序号及 runtime epoch。宿主拒绝错 nonce、
旧序号、非法 epoch、未知字段、重复字段和非预期 signal kind。

`TestLuaReceiptDrawingDecodedByHost` 从实际 Lua 纹理条带生成像素并由宿主解码；
`TestOpticalPairReaderRequiresFreshFrameForEachProof` 确认两次等待不能复用旧帧；
`TestIdleReceiptRecoveryUsesRealOpticalLifecycle` 保留焦点失效/恢复、异步完成、
世界离开和 opt-out 语义。禁用时不新增 frame、event、hook 或 timer。

新宿主仍可读旧单信号/双符号显示；旧宿主不识别新 envelope。因此实际使用需
配套更新 CLI 与 addon，不把相同候选版本号当作字节一致性的证明。
