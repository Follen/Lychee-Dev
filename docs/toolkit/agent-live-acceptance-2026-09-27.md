# Agent Live 可靠性验收合同

日期：2026-09-27。状态：拟议验收合同，配套[架构方案 r4](agent-live-architecture-2026-09-27.md)。当前生产实现没有因此获得通过结论。本文不替代 [design.md](design.md)、[implementation-status.md](implementation-status.md)、[regression.md](regression.md) 和当前[发布合同](release-2.0.6.md)；方案冻结后才同步权威合同。用户已批准实施与受管安装；当前验证事实见实施记录，没有创建定时自动化任务。

## 1. 验收目标及边界

可靠性分三件事验证：**不会做错，能够恢复，无法继续时明确停住。** 正常条件下无需玩家替 Agent 关闭输入框、抄协议或串接收尾；故障条件下不会为追求完成而误选目标、重跑未知代码或伪造成功。

不以“0 错误率”或整体测试通过率作为结论。不能保证游戏不崩溃、SV 永不被外部进程覆盖、任意 Lua 可被强制中止或所有外部副作用可回滚。这些条件恶化时仍必须满足目标隔离、不重放、证据诚实和有界退出。

Windows amd64 为唯一发行平台。支持端分别为 Retail 120100、Classic 50504、Titan 38002；Forever 16001 仅保留兼容 fixture，真机未验收不能混算通过。

## 2. 不可破坏的规则

| ID | 必须始终成立 | 怎样独立判断 |
| --- | --- | --- |
| INV-01 目标固定 | 任务中的安装、运行进程、角色和 build 不被重选；正常 reload 只更新已证明的 runtime | 将错误 PID 启动身份/HWND/actor/build 注入每个输入入口，非目标窗口的实际输入计数必须为零 |
| INV-02 先记意图 | 有副作用前已有可恢复意图、快照、准入和有效输入许可 | 独立记录磁盘提交与实际输入事件；任一步持久失败后不得出现对应输入或队列变更 |
| INV-03 至多执行一次 | 同一 operation 的任意 Lua 只进入一次；每个非幂等 reload 意图也不重复 | 游戏替身在用户代码入口及 reload 生效处独立计数；消息发送计数不能替代效果计数 |
| INV-04 一窗一主 | 任一时间最多一个 owner 驱动业务；首连也适用；任务内恢复借原 owner | 两个真实 CLI 进程/工作区的输入轨迹和共享记录交叉核对，失败者零业务输入 |
| INV-05 完成有依据 | 完整任务 complete=true 必有终局、受管资源释放、精确 ACK/退役、归属明确的显示清理和宿主释放 | 用独立只读校验器从归档证据重新推导，不能只读取 journal 的 complete/stage 字段 |
| INV-06 未知不变成功 | 结果未知不重跑；无正文不称 verified；abandon 不等于 ACK、停止执行或成功 | 删帧、断进程、损坏正文和丢 SV 后核对业务结果/报告/清理各字段，禁止由超时或空白画面推断成功 |
| INV-07 证据不串用 | operation、actor、build、runtime、nonce、摘要、观察下界全部关联 | 每次替换其中一个字段，证据必须被拒绝；正文归档后源 SV 被改写不改变已归档内容 |
| INV-08 无旧回调污染 | 受管任务终结后，旧回调在进入用户函数前即被拒绝；重连不抹除活动资源事实 | 在 Finish、超时、abandon、重连后触发保留的旧回调，用户函数计数为零或明确阻止新业务 |
| INV-09 容量有界 | 输入、队列、报告、日志、回调、终局凭据、捕获和重试均有预算 | 每个集合测试 0/1/上限/上限+1；达到上限不驱逐未决证据、不越界分配、不静默截断 |
| INV-10 恢复收敛 | 外部环境稳定且所需证据可得时恢复完成；缺必要条件时在调用预算内返回准确阻塞 | 使用可控时钟及固定响应脚本；区分成功收敛、可恢复 pending 和需新条件的 blocked，拒绝无限 resume |
| INV-11 禁用与兼容 | opt-in 功能禁用时不创建其资源；客户端差异只经 Compat/目录 | 计数帧/事件/hook/活动计时器；G1 的引导资源单列，未解决合同冲突不能豁免旧约束 |
| INV-12 结果不早封存 | 当前受管执行栈退出和清理结果采集后才封存；清理失败不被隐藏 | Finish 后抛错、清理逐项抛错和重复完成的独立回调轨迹与最终正文对照 |

这些规则通过公共执行/恢复入口或真实模块接口验证。不能为让测试通过而绕过生产接收、归属校验或最终完成判定。

## 3. 冻结前四道门槛

| 门槛 | 必须交付的证据 | 不通过时 |
| --- | --- | --- |
| G1 引导成本 | 明确常驻入口的帧/事件/hook/绑定清单及成本；首次安装、业务禁用、战斗登录、已有快捷键冲突的结果；与现有零成本合同一致的决策 | 不冻结首次唤醒接口，不声称同时满足永久入口与绝对零成本 |
| G2 单任务纵向链 | 一个完整任务从提交到终结；丢回执可观察；清理保有 owner；Finish/受管回调/资源清理准确；终局凭据容量及退休可恢复 | 不扩展到全量重写、UI 接线或发布 |
| G3 存储与升级 | 角色 SV 实际路径、初次落盘、重入、同账号不同角色、同报告位置多写入者、旧 runtime/新磁盘、新旧 schema 的证据 | 不发布角色级隔离或自动升级承诺 |
| G4 并发与崩溃 | 两个工作区、两个 CLI、两个窗口；意图→claim→准入、效果→证据、清理→释放各边界的故障注入轨迹 | 不宣称多实例健壮，不通过删除占用文件跳过失败 |

G1 是合同决策加验证；G2/G3 包含真机实验，G4 至少包含真实进程与文件系统实验。纯模型通过不代替这些证据。门槛内先做范围明确的小实验；失败时修订假设，不带着未证明前提铺开实现。

## 4. 可复现的故障注入

用同一驱动跑首次执行与恢复；控制 adapter 的输入结果、游戏事实、捕获流、时钟和写入失败。另以真实子进程强杀验证持久性，不能只抛一个函数错误模拟所有崩溃。每个案例独立临时工作区，恢复必须由新进程读取磁盘开始。

| 点位 | 注入位置 | 恢复必须满足 |
| --- | --- | --- |
| FP-01 | 本地意图/源快照/请求索引提交前后 | 提交失败不出现半个可执行任务；成功后同 key 仍指向同 OP |
| FP-02 | 共享 claim 临时文件同步前、原子发布后 | 未发布文件不构成正式 owner；发布成功一定能找到原意图；不暴露半截正式 JSON |
| FP-03 | 本地准入提交前后 | 同 owner/摘要补完准入；外来 owner 只报冲突；未完成准入零业务输入 |
| FP-04 | 队列合并/精确退役的临时文件与替换前后 | 文件要么旧完整版本，要么新完整版本；其他角色/任务条目和摘要保持不变 |
| FP-05 | 每个按键、每个报文字符、commit 意图落盘与 OS 接受之间 | 部分输入不执行；可能已提交时只观察；按键清理不误操作新目标，不以 OS 接受证明执行 |
| FP-06 | 游戏接收后、进入用户代码前、运行中、Finish 后 | 相同任务进入用户代码最多一次；同栈异常不丢失；未知不凭宿主阶段补跑 |
| FP-07 | 结果封存、最小错误凭据生成、SV 写盘、宿主归档前后 | 已有正文可恢复；缺失/损坏不冒充 verified；保存的失败不降格为普通超时 |
| FP-08 | ACK 生效后回执丢失、队列退役前后 | 精确查询或幂等重试只作用原任务；不再次执行；报告仍可用 |
| FP-09 | 资源清理、显示退役、清屏观察及 owner 释放前后 | 未收完不释放；释放后旧恢复零游戏输入，不能隐藏新任务回执 |
| FP-10 | abandon、安装维护标记/替换、旧 runtime 重入前后 | abandon 不证明 runtime 空闲；维护不饿死旧恢复；不静默激活不匹配协议或丢失其他任务 |

每个点至少覆盖：调用前失败、效果发生后返回失败、进程强杀。只适用于纯内存的 Lua 点位用受控 Lua 环境和相关真机场景验证，不能声称强杀 CLI 覆盖了 Lua 原子性。正常文件系统下的崩溃恢复与文件系统损坏分开记录；后者应明确保留证据并阻塞，不能“自动修复”为成功。

调度覆盖两个 CLI、两个工作区、两个窗口的成对交错；对 claim/CAS、commit、ACK/释放等有限关键事件穷举可达交错。候选验证再跑至少 10,000 个可重放调度种子，记录模型版本、种子和失败最短轨迹；随机次数不能替代指定反例。对协议/报告解析进行有大小和时间预算的 fuzz，失败输入进入固定回归集。

## 5. 必须通过的场景矩阵

下列 P0 全部阻断对应新 Live 架构交付；P1 在声明对应 UI/业务能力时同样阻断。每行必须拆成可独立记录的具体参数案例，不能一个 passed 覆盖未运行组合。

| ID / 级别 | 场景与参数 | 明确的通过判据 |
| --- | --- | --- |
| LIVE-01 / P0 | 首次安装、业务关闭、无 session、已启用、升级后 | 按 G1 合同可启动；无循环依赖；身份未确认前零业务输入 |
| LIVE-02 / P0 | 正常 execute 与已完成任务重复调用 | 初次完整收尾；同 key/OP 重试零输入、零新业务任务，读取同一归档 |
| LIVE-03 / P0 | 并发相同 key；同 key 更换代码/预算/actor/pin；窗口标题变更 | 相同请求同 OP；变更不可变输入冲突；标题等展示字段不产生新执行 |
| LIVE-04 / P0 | 原文件删除、probe 名称改指向、CLI/客户端退出 | 按 OP 使用冻结快照；客户端重启不自动迁移旧任务；离线可读已有结果 |
| LIVE-05 / P0 | 唯一回执在发送返回前出现；旧帧/晚帧/回执替换 | 不漏唯一有效帧；旧帧无权限；普通回执丢失仍可观察原任务，无重跑 |
| LIVE-06 / P0 | 部分报文、重复唤醒/提交、坏 checksum、旧 challenge、晚 close | 非相关提交不执行；晚关闭最多影响输入，不能终结/清理新业务；无残留焦点或无界重试 |
| LIVE-07 / P0 | 同步成功/错误、语法错、Finish 后抛错、重复/递归 Finish | 准确的唯一终局；没有“已存成功正文但调用栈失败”的矛盾 |
| LIVE-08 / P0 | Async 边界、晚调用 Async、晚完成、超时同时到达 | 截止从开始算；受管回调只进入合法任务；成功/失败裁决确定，恢复不续业务时间 |
| LIVE-09 / P0 | 首/中/末清理抛错、清理时会话改变、重复 resume | 错误可见且继续其他清理；报告可用但未释放不 complete；任意清理不盲目重试 |
| LIVE-10 / P0 | 报告编码/secret/深度/大小失败，最小终局容量满 | 已知失败有可关联终局；新任务所需容量执行前预留；不能写完整报告不伪造 verified |
| LIVE-11 / P0 | 已有报告但 ACK 丢失、ACK 后清屏失败、释放时崩溃 | 只恢复剩余义务；未清理一直持有 owner；另一任务接管后旧恢复不发输入 |
| LIVE-12 / P0 | 黑帧、ROI 漏码、遮挡、缩放、码无法解出 | 不凭零二维码完成；已有报告保留；有终结凭据但显示证据不足则 pending/unknown |
| LIVE-13 / P0 | abandon 在 prepared/部分输入/运行/已报告未ACK；随后新任务 | 精确退役、保留未知；旧回调/资源存在时不能依据 Queue.Reset 或空磁盘放行 |
| LIVE-14 / P0 | 两 workspace 同窗首连/执行/恢复；两 CLI 同 OP | 一个驱动者；竞争者返回实际 owner；同 OP 恢复不重复执行，不靠删除锁解冲突 |
| LIVE-15 / P0 | 同安装不同角色/账号、不同安装相同名字、并行 report/reload | 队列原子合并且精确删除；报告/nonce/代码不串用；独立目标可同时推进 |
| LIVE-16 / P0 | 同报告位置两个可观察游戏写入者、未知账号路径 | 在业务副作用之前拒绝或要求消除歧义；不能以宿主串行化宣称 SV 隔离 |
| LIVE-17 / P0 | PID 重用、HWND替换、换角色、换build、转区/战斗/最小化 | 错目标零输入；就绪丢失有界退出；一个窗口不可用不阻塞独立窗口 |
| LIVE-18 / P0 | 首次角色SV、新旧schema、旧runtime/新磁盘、安装维护竞争 | 正确定位并核验；旧证据只读保留；新准入受维护阻止，旧恢复不会被持锁等死 |
| LIVE-19 / P0 | 绝对reload每一步中断、游戏未响应、reload结果未知 | 只作用固定目标；记录每步；未知不重复reload；生效需相关新runtime证据 |
| LIVE-20 / P0 | UI关闭/切页/隐藏QR、手工启停与CLI执行交错 | UI不改变CLI完成范围或覆盖其报告；冲突动作有解释；本地工作台仍可独立使用 |
| CLI-01 / P0 | describe/help/parser/skill、完整任务与旧原子命令 | 同一契约表；未实现不宣传；原子ACK不能提前完成新完整任务；旧命令合同不静默改变 |
| CLI-02 / P0 | business失败、pending、取消、只读status、JSONL中断 | 新execute/resume准确exit 5/6/7；status exit0只是查询成功；JSONL缺合法end不完整 |
| SKILL-01 / P0 | 正常任务、已报告未清理、回执丢失、多候选、外部阻塞 | 目标明确后完成授权闭环；恢复原OP；不止步QR/报告；不无限resume、不重复索要已有授权 |
| SKILL-02 / P1 | source→data→live、独立bugs、connect-only、reload-only | 固定引用传递；选择对应完成目标；不强迫非Live业务进入桥状态机 |
| UI-01 / P1 | 八页面、设置、接收窗口；中英文、长文本、空态、小窗口 | 无截断关键动作/重叠；正文14–16、元数据≥13；圆角真实绘制；协议文本不压倒用户信息 |
| UI-02 / P1 | 快捷键录入/保存/重置、焦点、Enter、战斗、半初始化异常 | 有效绑定与显示一致，不覆盖账号绑定；异常释放输入；普通聊天Enter仍正常 |
| UI-03 / P1 | 同步入口、异步执行、超时、成功/失败终结 | 业务入口之前接收框/输入遮罩隐藏、焦点释放、接收计时器取消；异步等待无握手 QR；终局仍有相关报告，完整任务收尾确认显示清除 |
| PARITY-01 / P1 | 原子Live、工作台、source/data/assets原有矩阵 | 原有期望仍通过；改变行为必须有明确合同差异和对应证据，不以重写为由删除用例 |

## 6. 容量、退出与长期运行

下表为既有预算或拟议冻结要求，不是已测结果。未来若修改数字，须同步契约/Go/Lua/skill和上限反例；不能只增大预算掩盖泄漏。

| 资源 | 验收预算与检查 |
| --- | --- |
| 队列/源码 | 保留16条、单条256 KiB、总源1 MiB；第17条或多1字节在执行前拒绝，原队列不变 |
| 报告 | 单正文512 KiB，既有最多100条/总16 MiB；以实际接受数量验证边界，未确认报告不被自动驱逐 |
| 日志/清理 | 每探针100条且32 KiB日志、最多16个注册清理；截断显式，secret错误不进入日志正文 |
| 终局凭据 | 每runtime拟最多16槽、单槽编码2 KiB、合计32 KiB；最长合法字段也须容纳；未归档不驱逐；退休/跨reload反例必须在G2/G3通过 |
| 输入 | Go/Lua统一最大报文；最大合法报文的字符节奏+读回+提交必须装得进接收预算，否则发送前拒绝；额外字符、无效UTF/控制字符拒绝 |
| 重试/等待 | 每调用保存确定的截止与重试上限；无新证据不空转。正常可响应宿主下，到截止即取消观察并在5秒收尾余量内返回，不等待游戏线程自行恢复 |
| 捕获/证据 | 使用现有workspace与capture预算；保留中的任务引用不可被普通GC删除；磁盘满不能先ACK再发现报告未归档 |

同步 Lua 卡死只验证宿主有界返回和保持未知，不能验证成“游戏任务已取消”。宿主系统或磁盘本身不响应不受上述5秒保证；记录环境失败，不伪造内部完成。

长跑要求：可控环境连续1,000个完整任务；每个支持端真机至少连续20个完整任务，穿插失败、恢复和清理，之后仍能启动下一任务。记录冷/热启动、投递、reload、报告、清理分段耗时，不把游戏加载时间算作CLI计算性能。

资源判定使用可枚举的owner/驱动锁/事件/计时器/捕获句柄/队列条目和有界缓存：每个完成任务的活动资源归零，固定初始化缓存稳定，不随任务数增长。原生WoW帧不能假设可销毁，采用有界复用并验证停止事件和OnUpdate；禁用成本按G1区分引导与可选功能。内存曲线作为辅助证据，不能替代这些准确计数。

## 7. 真机与UI证据

| 维度 | 最少覆盖 |
| --- | --- |

原生游戏画面证据必须用WGC。每个视觉变更保存同窗口/相同缩放的before/after；圆角、字号、焦点与动作可见性既需图像也需交互。离线截图/绘图stub不能替代真机通过。交互桌面验收由owner人工记录，不增加self-hosted CI桌面门禁。

记录最小字段：caseId、revision/脏树manifest摘要、fixture版本/随机种子、CLI/磁盘addon/运行addon版本、完整目标、输入参数、预期、实际、状态、日志/报告/capture引用及摘要。候选归档必须能离线复核；敏感本地路径/角色信息按现有证据访问规则保留，不为了演示公开原始日志。

结果状态严格为 passed/failed/blocked/not_run/not_applicable。blocked写明已尝试及具体障碍；没运行保持not_run；not_applicable必须有范围依据。不能用一次Retail成功覆盖Classic/Titan，也不能把模型的Forever通过写成支持端通过。

## 8. 通过顺序与停止条件

1. 完成G1–G4证据，确认协议、存储和公开接口可实施，再冻结权威合同。当前未知项不靠同意文档自动通过。
2. 以现有反例先建立失败回归；每批修改build/vet及受影响模块测试通过，再进入下一批。测试真实接口，不照抄实现阶段表当判定依据。
3. 完整候选执行强制Lua 5.1的全套Go测试、相关Node/包/skill/version门禁；接着受管安装并完成三客户端、并发和长期运行验收。
4. 所有适用P0和声明能力P1通过，关键资源计数稳定，无未关闭的不安全重放/串目标/误报完成/正常崩溃不可恢复缺陷，才进入既有发布流程。

任何反例违反INV-01..12，立即停止扩大安装/发布；保留原OP和证据，修复后跑失败用例及受影响交错。不得修改预期来接纳已知错误，不得清理未决记录后重跑到一次成功就算通过。已知可验证业务失败是产品允许的结果，不是测试失败；判断重点是结果是否准确和收尾是否符合合同。
